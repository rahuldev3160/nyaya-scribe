## Symptom
User reported GS Mains topics showing "0 answered / N pending" with no way to write answers. Investigating why 0/221 model answers exist (per HANDOFF's known Option B backlog item) surfaced a worse problem underneath: a large fraction of the "question_text" values in `pyq_questions` (seeded by `migrations/m055_seed_gs_mains_pyqs.py`, `exam_id='upsc_gs_mains'`) are not UPSC exam questions at all.

## Evidence
Sampled rows from GS1/GS2/GS3 (`paper_id` gs1/gs2/gs3, 62+29+37 = 128 of 221 rows):
```
"Nishant Rajput 02/05/ at 11:16 am - Reply How to download vijay sahu 07/05/ at 8:52 pm - Reply press CTRL + P..."
"Komal 08/03/ at 4:34 pm - Reply It helps me a lot sir Thank you 😊🙏"
"✍ Mains Compulsory 💾 Essay Past Papers Essay: How not to write UPSC Essay Paper Papers Mock Essays GSM1..."
```
This is blog-comment-section and page-navigation text — almost certainly scraped from a coaching site (Mrunal.org-style) article about GS papers, where the scraper grabbed comments/nav furniture instead of (or mixed with) the actual question text. A conservative regex pass (matching "Reply", timestamps, "Thank you sir", "topic wise", "lecture video", etc.) flags:
- gs1: 45/62 (73%)
- gs2: 26/29 (90%)
- gs3: 24/37 (65%)
- gs4: 1/93 (~1%)

A random-sample eyeball check (6 rows each from gs1/gs2/gs3) found **6/6 junk in every paper** — the true contamination rate in gs1–gs3 is likely higher than the conservative regex count, close to total. **GS4 (93 rows) looks clean** — sampled rows are genuine ethics-style case-study stems ("Case study: public org dilemma- Shutting down pollutant MSME (, 20m)").

## Why this matters more than the "0 model answers" framing in HANDOFF/memory
You cannot generate a coherent model answer to "Komal ... Thank you sir 😊🙏". Any attempt to run the existing answer-generation pipeline (same one used for IES/Eco Optional/Essay/Ethics) against gs1/gs2/gs3 as-is will either fail loudly or — worse — the model will hallucinate a plausible-sounding answer to noise, silently corrupting the dataset in a way that's hard to detect later (looks like a real Q&A pair on inspection).
