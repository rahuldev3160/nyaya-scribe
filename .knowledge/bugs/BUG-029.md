# BUG-029 — _parse_json non-greedy regex breaks on nested JSON

**Status:** FIXED | **Severity:** HIGH | **Session:** S45 | **Category:** batch-generation

## Symptom
`PARSE ERROR ethics_0002: No valid JSON found in response` during test batch retrieval. Section B STAKE answers failing to parse even when the response was valid JSON.

## Root Cause
`_parse_json()` in `scripts/generate_model_answers_batch.py` used a non-greedy regex `{.*?}` to extract JSON from markdown code fences. Non-greedy stops at the first `}` inside the object — any nested JSON (arrays, nested objects) caused it to extract an incomplete fragment, which then failed `json.loads`.

```python
# BROKEN: stops at first }
match = re.search(r"```(?:json)?\s*(\{.*?\})\s*```", text, re.DOTALL)
```

## Fix
Three-tier fallback that never uses non-greedy matching:
1. Direct `json.loads(text)` — handles clean responses
2. Strip markdown fences with `re.sub` (removes all fence markers), retry `json.loads`
3. `text.find("{")` + `text.rfind("}")` — extracts outermost braces, retry `json.loads`

## File
`scripts/generate_model_answers_batch.py` — `_parse_json()` function

## Pattern
BATCH-PARSE-001 — always use `rfind("}")` not non-greedy regex when extracting JSON from LLM output.
