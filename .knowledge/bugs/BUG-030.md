# BUG-030 — max_tokens=2048 truncates Section B STAKE answers mid-JSON

**Status:** FIXED | **Severity:** HIGH | **Session:** S45 | **Category:** batch-generation

## Symptom
All 34 Section B (STAKE framework) ethics answers failed with `stop_reason: max_tokens` and parse errors after the full batch retrieval. Section A (IDEA-U) answers all succeeded.

## Root Cause
`build_ethics_b_request()` used `max_tokens=2048`. Section B answers include five STAKE fields (stakeholders, tension, analysis, decision, execution) + `full_answer_text` combining all of them — responses ran ~9000 characters (~3000-4000 tokens), consistently exceeding the 2048 limit. JSON was truncated mid-object, making it unparseable.

Section A answers are ~600-700 tokens (150 word target); Section B are ~3000-4000 tokens (200-400 words per sub-part × 5 steps + full prose).

## Fix
Changed `max_tokens=2048` → `max_tokens=4096` in `build_ethics_b_request()`. 33/34 items resolved on retry; 1 remaining item resolved on a 2nd retry.

## File
`scripts/generate_model_answers_batch.py` — `build_ethics_b_request()` function

## Rule Going Forward
Any prompt that asks for both structured JSON fields AND a `full_answer_text` prose field needs `max_tokens=4096`. If both structured + prose output exist in the same JSON response, token usage doubles.
